записи, подключить клиентов и разобраться в устройстве проекта. Общее описание
и быстрый старт — в [README](../README.md).

## Что понадобится

- Сервер с **Ubuntu 22.04 или новее** и systemd
- Права **root**
- **Публичный IPv4-адрес** — он попадает в сертификаты, без него IKEv2, SSTP и
  OpenVPN работать не будут
- Для доверенного сертификата SSTP — **домен**, A-запись которого уже указывает
  на этот сервер

Сервер за NAT без публичного адреса не подойдёт.

## Установка на сервер

`atlas` — один статический бинарник без зависимостей. **Компилировать ничего не
нужно**: готовые сборки лежат в репозитории.

### Одной командой (основной способ)

Выполните на сервере под root:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/Ground-Zerro/AtlasTunnel/main/install.sh)
```

Скрипт сам определит архитектуру (x86_64 или aarch64), скачает нужный бинарник из
каталога `bin/` репозитория, **сверит контрольную сумму SHA-256** и сразу запустит
выбор протоколов.

### Вручную

Если нет доступа в интернет с сервера, скачайте бинарник заранее и скопируйте:

```bash
scp bin/atlas-x86_64-linux root@сервер:/usr/local/bin/atlas
ssh root@сервер chmod +x /usr/local/bin/atlas
```

### Выкатка на несколько серверов

С машины, где есть исходники:

```bash
tools/deploy.sh root@srv1 root@srv2
```

Скрипт определяет архитектуру каждого сервера, копирует нужный бинарник, сверяет
контрольную сумму на удалённой стороне и ставит в `/usr/local/bin/atlas`. Ошибка на
одном сервере не прерывает остальные — в конце выводится сводка.

## Какой протокол выбрать

| Протокол | Шифрование | Порты | Когда выбирать |
|----------|-----------|-------|----------------|
| **IKEv2/IPsec** | AES-256 | UDP 500, 4500 | Основной выбор: быстрый, современный, переживает смену сети на телефоне |
| **SSTP** | TLS | TCP 443 | Когда провайдер режет VPN: неотличим от обычного HTTPS |
| **OpenVPN** | AES-256-GCM | UDP 1194 | Максимальная совместимость, готовый файл профиля |
| **L2TP/IPsec** | AES-256 + PSK | UDP 1701, 500, 4500 | Старые устройства без поддержки IKEv2 |
| **PPTP** | MPPE-128 | TCP 1723 + GRE | Только если ничего другого не поддерживается |
| **L2TP** | **нет** | UDP 1701 | Трафик идёт открытым текстом. Только для доверенной сети |
| **IKEv2** | **null cipher** | UDP 500, 4500 | Без шифрования, ради скорости. Понимайте риск |

### Что нельзя совмещать

`/etc/ipsec.conf` монопольно принадлежит одному протоколу, поэтому
**L2TP/IPsec, IKEv2 и IKEv2/IPsec взаимно исключают друг друга** — одновременно
работает только один из трёх. Установщик проверяет это до первой записи на диск.
Если конфликтующий протокол уже стоит, он будет заменён с явным подтверждением.

Остальные сочетания безопасны: PPTP + L2TP/IPsec + SSTP + OpenVPN уживаются.

### Ограничения, о которых стоит знать заранее

- **PPTP часто не работает** не по вине сервера: протокол требует GRE, который
  режут многие провайдеры и почти все мобильные операторы. Apple убрала
  поддержку PPTP из macOS 10.12 и iOS 10 — на этих системах его нет вовсе.
- **L2TP без IPsec не шифрует трафик.** Это не недоработка, а сам протокол.
- **SSTP с самоподписанным сертификатом** потребует импорта сертификата на
  каждом клиенте. С доменом и Let's Encrypt этого не нужно.

### Пакеты, удалённые из свежих выпусков Ubuntu

`pptpd` удалён начиная с **Ubuntu 24.04**. Проект рассчитан на развёртывание
устаревших VPN-протоколов на актуальных системах, поэтому такие пакеты берутся из
официального архива прошлого LTS — по умолчанию **jammy (22.04)**.

Как это устроено:

- подключается официальный архив `archive.ubuntu.com` (или `ports.ubuntu.com` для
  arm64) с **проверкой подписи** штатным ключом `ubuntu-archive-keyring`;
- недостающие пакеты закрепляются за архивом с приоритетом 991, весь остальной
  архив — с приоритетом 100. Поэтому из старого выпуска приходит **только то,
  чего нет в текущем**: для PPTP на 24.04 это ровно `pptpd` и `bcrelay`, а `ppp`,
  `libwrap0` и остальные зависимости остаются из noble;
- установленные из архива версии фиксируются через `apt-mark hold`, иначе
  очередной `apt upgrade` подменил бы или удалил пакет;
- список подменённых пакетов ведётся в `/etc/atlastunnel/legacy.conf`, отражается
  в `atlas doctor` и снимается при удалении протокола.

⚠️ Такие пакеты **не получают обновлений безопасности текущего выпуска**.
Предупреждение показывается на экране подтверждения и в выводе `--yes`.
Отказаться можно флагом `--no-legacy-packages` — тогда установка протокола,
требующего архив, прервётся.

### SSTP: как устроен сервер

Демона SSTP нет ни в одном выпуске Ubuntu — в репозиториях только `sstp-client`.
Сервер (`sorz/sstp-server`) ставится из PyPI в отдельный venv `/opt/atlastunnel/sstp`,
чтобы не трогать системный Python. Параметры передаются флагами в systemd-юните,
а не конфиг-файлом: формат конфига между версиями демона несовместим.

Требуется **Python ≥ 3.12**: версия `sstp-server 0.6.0`, которую pip выбирает для
Python 3.10, падает с SEGV в C-расширении при первом же подключении клиента.
Если системный Python ниже, установщик подключает `ppa:deadsnakes/ppa` и ставит
`python3.12` — с явным предупреждением. Версия пакета проверяется отдельно:
установка обрывается, если получилась ниже 0.7.

Пакет `sstp-client` несёт `sstp-pppd-plugin.so`, через который демон получает от
pppd ключи MPPE для crypto binding. Ставится только при версии **1.0.19+**:
плагин из 1.0.17 (Ubuntu 22.04) несовместим с `sstp-server 0.7.2` — клиент
обрывает сессию сразу после подключения. Если несовместимая версия уже стоит,
установщик снимает её — сервер сам определяет отсутствие плагина и не требует
crypto binding от клиентов (`sorz/sstp-server` штатно поддерживает эту схему).
Реальный Linux-клиент `sstp-client` тоже умеет работать без плагина — но
только при определённом способе запуска, см.
[«Нюансы запуска Linux-клиентов»](#нюансы-запуска-linux-клиентов).

#### Сертификат: самоподписанный или Let's Encrypt

Выбор даётся при установке — в TUI отдельным экраном, в CLI флагом `--domain`.

| | Самоподписанный | Let's Encrypt |
|---|---|---|
| Домен | не нужен | обязателен, A-запись на этот сервер |
| Порт 80 | не нужен | занимается certbot на время проверки |
| На клиенте | требуется импорт сертификата | ничего не нужно |
| Продление | не требуется (10 лет) | автоматически, `certbot.timer` |

```bash
atlas install --protocols sstp --yes                              # самоподписанный
atlas install --protocols sstp --domain vpn.example.com --yes     # Let's Encrypt
atlas install --protocols sstp --domain vpn.example.com --email me@example.com --yes
```

Перед выпуском проверяется, что домен разрешается именно в адрес этого сервера и
что порт 80 свободен — иначе установка прерывается до каких-либо изменений.
Юнит демона указывает прямо на `/etc/letsencrypt/live/<домен>/`, а deploy-хук
`/etc/letsencrypt/renewal-hooks/deploy/atlastunnel.sh` перезапускает службу после
продления, поэтому новый сертификат подхватывается без участия человека.

## Первая установка

### Через интерфейс

```bash
atlas install
```

Полноэкранный выбор протоколов:

```
 ATLASTUNNEL · установка v5.0.0                          выбор протоколов
╭ Уже установлено ───────────────────────────────────────────────────────╮
│ ничего не установлено — выполняется первичная настройка                │
╰────────────────────────────────────────────────────────────────────────╯
 ▸ [✓] PPTP            Максимальная скорость, шифрование MPPE-128
   [ ] L2TP            Без шифрования, минимальные накладные расходы
   [✓] L2TP/IPsec      Шифрование IPsec с общим ключом PSK
   [ ] IKEv2           Null cipher, скорость вместо шифрования
   [ ] IKEv2/IPsec     Шифрование IPsec с CA-сертификатом
   [ ] SSTP            SSL поверх TCP 443, проходит через firewall
   [✓] OpenVPN         Универсальное решение, UDP 1194
 ────────────────────────────────────────────────────────────────────────
 ↑↓ выбор · SPACE отметить · A совместимый набор · ENTER далее · Q выход
```

| Клавиша | Действие |
|---------|----------|
| `↑` `↓` `PgUp` `PgDn` `Home` `End` | Перемещение |
| `SPACE` | Отметить или снять протокол |
| `A` | Отметить наибольший совместимый и доступный набор |
| `ENTER` | Дальше |
| `Q` / `ESC` | Прервать установку |

Если выбран SSTP, следующий экран предложит выбрать сертификат — самоподписанный
или Let's Encrypt с вводом домена. Затем экран подтверждения, где перечислено всё,
что будет сделано, и только после него начинаются изменения на диске.

### Без интерфейса

```bash
atlas install --protocols ikev2-ipsec,openvpn --yes
atlas install --protocols ikev2-ipsec,sstp --yes
atlas install --all --yes                              # совместимый набор
atlas install --protocols sstp --user admin --yes
atlas install --protocols sstp --domain vpn.example.com --yes
```

Флаг `--yes` обязателен: без него команда откажется работать, чтобы установка не
запустилась случайно.

### Что вы получите

По завершении выводятся параметры доступа — **сохраните их сразу**:

```
  IP сервера : 203.0.113.10
  Логин      : vpnuser
  Пароль     : Niq8zQneN7yCUXfE
  PSK        : y25Nt2n2cWaj8Gn7EU4SvkZA
  Профиль    : /etc/atlastunnel/clients/vpnuser.ovpn
```

Пароль всегда можно посмотреть позже: `atlas client list <протокол> --reveal`.

### Если установка прервалась

Все изменённые файлы автоматически возвращаются в исходное состояние:

```
   ! изменения отменены, восстановлено файлов: 6
Ошибка: генерация сертификата: parsing public key failed
```

Ранее установленные протоколы продолжают работать. Подробности всех выполненных
команд — в `/var/log/atlastunnel/atlas.log`.

   IKEv2/IPsec       ● ЗАПУЩЕН   Шифрование IPsec с CA-сертификатом
   OpenVPN           ● ЗАПУЩЕН   Универсальное решение, UDP 1194

 ENTER открыть · S запустить все · T остановить все · R перезапустить · D диагностика · Q выход

|---------|----------|

## Учётные записи

### В интерфейсе

Экран протокола → **Клиенты**. Пароли скрыты, `M` показывает их.

```
 ATLASTUNNEL · PPTP · клиенты                                     всего: 2
 ▸   1. vpnuser                 ••••••••••••••••
     2. tester                  ••••••••••••••••
 ─────────────────────────────────────────────────────────────────────────
 A добавить · D удалить · P новый пароль · M показать пароли · ESC назад
```

| Клавиша | Действие |
|---------|----------|
| `A` | Добавить (логин запрашивается, пароль генерируется) |
| `D` | Удалить выбранного |
| `P` | Сгенерировать новый пароль |
| `M` | Показать или скрыть пароли |
| `ESC` | Назад |

### Из командной строки

```bash
atlas client list ikev2-ipsec              # пароли скрыты
atlas client list ikev2-ipsec --reveal
atlas client add ikev2-ipsec ivanov        # пароль будет сгенерирован
atlas client passwd ikev2-ipsec ivanov
atlas client remove ikev2-ipsec ivanov
```

Логин: 3–32 символа, латинские буквы, цифры, дефис, подчёркивание.

Учётные записи **раздельны по протоколам**. PPTP, L2TP и SSTP хранятся в общем
файле `/etc/ppp/chap-secrets`, но каждый протокол видит и меняет только свои
записи — добавление клиента SSTP не тронет пользователей PPTP.

OpenVPN учётными записями не управляется: он использует сертификаты, и профиль
`.ovpn` создаётся при установке.

## Подключение клиентов

Общие параметры: **адрес сервера**, **логин**, **пароль**. Дополнительно — PSK
для L2TP/IPsec и CA-сертификат для IKEv2.

### IKEv2/IPsec — рекомендуемый

Сначала скопируйте CA-сертификат на устройство:

```bash
scp root@сервер:/etc/atlastunnel/ca-cert.pem .
```

**Windows.** Откройте `ca-cert.pem` → Установить сертификат → Локальный компьютер
→ поместить в «Доверенные корневые центры сертификации». Затем Параметры → Сеть и
Интернет → VPN → Добавить: тип «IKEv2», тип входа «Имя пользователя и пароль».

**macOS / iOS.** Откройте файл сертификата и добавьте в Связку ключей; на iOS
после установки профиля включите доверие в Настройки → Основные → Об этом
устройстве → Доверие сертификатам. Далее Настройки → VPN → IKEv2, укажите адрес
сервера в полях «Сервер» и «Удалённый ID».

**Android.** Установите приложение **strongSwan**. Настройки → Безопасность →
Установить сертификат из хранилища, затем в strongSwan создайте профиль типа
«IKEv2 EAP (Username/Password)» и выберите импортированный CA.

**Linux (NetworkManager).** Понадобится `network-manager-strongswan`. Тип
соединения — IKEv2, аутентификация EAP, укажите файл CA-сертификата.

### SSTP

**Windows** — поддержка встроена. Параметры → VPN → Добавить, тип «SSTP», адрес —
домен или IP сервера.

Если сертификат самоподписанный, сначала импортируйте его в «Доверенные корневые
центры сертификации», иначе подключение будет отклонено:

```bash
scp root@сервер:/etc/sstp-server/cert.pem .
```

При установке с `--domain` и Let's Encrypt импорт не нужен — сертификат доверенный.

**Linux.** Пакет `sstp-client`:

```bash
sudo sstpc --user vpnuser --password ПАРОЛЬ vpn.example.com \
     usepeerdns require-mschap-v2 noauth
```

macOS, iOS и Android SSTP штатно не поддерживают — нужны сторонние клиенты.

### L2TP/IPsec

Понадобится **общий ключ (PSK)** — он показан после установки и на экране
протокола в менеджере.

**Windows.** Параметры → VPN → Добавить, тип «L2TP/IPsec с общим ключом».

**macOS / iOS.** Настройки → VPN → Добавить конфигурацию → L2TP. Заполните
«Сервер», «Учётная запись», «Пароль» и «Общий ключ».

**Android.** Настройки → Сеть → VPN → тип «L2TP/IPSec PSK».

### OpenVPN

Профиль уже собран со всеми ключами внутри:

```bash
scp root@сервер:/etc/atlastunnel/clients/vpnuser.ovpn .
```

Импортируйте его в OpenVPN Connect (Windows, macOS, Android, iOS) или:

```bash
sudo openvpn --config vpnuser.ovpn
```

### PPTP

**Windows.** Параметры → VPN → Добавить, тип «PPTP».
**Android.** Настройки → VPN → тип «PPTP».
**Linux.** Пакет `pptp-linux` или NetworkManager.

На macOS и iOS PPTP не поддерживается начиная с macOS 10.12 и iOS 10.

## Нюансы запуска Linux-клиентов

Для Windows, macOS, iOS и Android достаточно инструкций из предыдущего
раздела. На Linux у двух протоколов есть неочевидные тонкости конкретных
клиентских пакетов — без них подключение либо не проходит аутентификацию,
либо зависает без внятной ошибки.

### IKEv2/IPsec: нужен отдельный пакет плагинов strongSwan

Пакет `libcharon-extra-plugins` в Ubuntu **не содержит** `eap-mschapv2` — без
него strongSwan-клиент (в том числе `network-manager-strongswan`) не может
пройти аутентификацию логином/паролем и завершает согласование ошибкой вида
`EAP method not supported, sending EAP_NAK`. Нужный плагин лежит в отдельном
пакете:

```bash
sudo apt install libcharon-extauth-plugins
```

Это обычный пакет из репозитория Ubuntu 22.04, собирать ничего не нужно.
Windows, macOS, iOS и Android несут EAP-MSCHAPv2 «из коробки», этой
тонкости не касаются.

### SSTP: как правильно запускать sstp-client

Распространённый в интернете рецепт — прописать `sstpc` в pppd-peer файле
через pty:

```
pty "sstpc --cert-warn --nolaunchpppd vpn.example.com"
```

На Ubuntu 22.04, где штатный `sstp-client 1.0.17` несовместим с плагином
сервера (см. [«Какой протокол выбрать» → SSTP: как устроен
сервер](#sstp-как-устроен-сервер)), этот способ **не работает**: в режиме
`--nolaunchpppd` pppd запускает sstpc как пассивный «модем», и клиент не
видит поток pppd, чтобы вычислить MPPE-ключи без плагина — согласование PPP
зависает без объяснения причины.

Правильный способ — дать `sstpc` самому запустить pppd, передав логин и
пароль прямо в командной строке (это же указано в [«Подключение
клиентов» → SSTP](#sstp)):

```bash
sudo sstpc --user vpnuser --password ПАРОЛЬ vpn.example.com \
     usepeerdns require-mschap-v2 noauth
```

В этом режиме sstpc сам вычисляет MPPE-ключи из CHAP/MSCHAPv2-обмена внутри
управляемого им же pppd, и crypto binding проходит без плагина — независимо
от того, установлен ли `sstp-pppd-plugin.so` на сервере.

## Командная строка

Всё, что делает TUI, доступно без него — для Ansible, cloud-init и CI.

```bash
atlas                                          # TUI-менеджер
atlas install                                  # TUI-установщик
atlas install --protocols pptp,l2tp-ipsec --yes
atlas install --all --yes                      # совместимый набор
atlas install --protocols ikev2-ipsec --user admin --yes
atlas install --protocols pptp --yes --no-legacy-packages   # запретить архивы
atlas install --protocols sstp --domain vpn.example.com --yes            # SSTP с Let's Encrypt
atlas install --protocols sstp --domain vpn.example.com --email me@example.com --yes

atlas list                                     # состояние протоколов
atlas list --json
atlas start | stop | restart [протокол]        # без аргумента — все

atlas client list pptp [--reveal]
atlas client add pptp ivanov                   # пароль генерируется
atlas client passwd pptp ivanov
atlas client remove pptp ivanov

atlas doctor [--json]                          # код 2, если найдены ошибки
atlas uninstall openvpn --yes
```

Все команды берут межпроцессную блокировку `/run/atlastunnel.lock`, поэтому два
одновременных запуска не испортят файл паролей.

## Диагностика

```bash
atlas doctor
```

Сверяет заявленное состояние (маркеры в `/etc/atlastunnel`) с фактическим:
состоянием юнитов, наличием конфигов, учётными записями, слушающими портами и
монопольным владением файлами.

```
[ошибка] /etc/ipsec.conf
    на файл претендуют несколько протоколов: L2TP/IPsec, IKEv2/IPsec — работоспособен только последний установленный
    → оставьте один протокол: atlas uninstall l2tp-ipsec
[внимание] PPTP
    нет ни одной учётной записи — подключиться невозможно
    → atlas client add pptp <логин>
```

Код выхода: `0` — норма или предупреждения, `2` — есть ошибки. Удобно для
мониторинга: `atlas doctor --json`.

### Клиент не подключается

**Сначала проверьте сервер:**

```bash
atlas doctor
atlas list
journalctl -u strongswan-starter -n 50    # или pptpd, xl2tpd, sstp-server
```

**Если сервер в порядке, проблема на пути до него.** Быстрая проверка — попробуйте
подключиться через мобильный интернет другого оператора. Если оттуда работает,
трафик режет ваш провайдер или маршрутизатор.

Типовые причины по протоколам:

| Симптом | Вероятная причина |
|---------|-------------------|
| PPTP: соединение устанавливается, но зависает | Провайдер режет GRE. Перейдите на SSTP или IKEv2 |
| L2TP/IPsec: таймаут | Блокируется UDP 500/4500 или мешает NAT без IPsec passthrough |
| SSTP на Windows: ошибка сертификата | Самоподписанный сертификат не импортирован |
| IKEv2: «сертификат не доверен» | CA-сертификат не установлен на клиенте |
| Подключается, но нет интернета | Проверьте `atlas doctor` и правила iptables |

**Журналы.** Все команды, выполненные `atlas`, пишутся в
`/var/log/atlastunnel/atlas.log`.

## Транзакционность

Каждый файл, который установщик собирается изменить, сначала попадает в снимок.
При любой ошибке — недоступный пакет, упавшая генерация сертификата, не
поднявшаяся служба — все файлы возвращаются в исходное состояние:

```
== IKEv2/IPsec
   · Выпуск серверного сертификата на 31.59.37.185
   ! изменения отменены, восстановлено файлов: 6

Ошибка: генерация /etc/ipsec.d/certs/server-cert.pem: parsing public key failed
```

После такого отката ранее установленные протоколы продолжают работать, а
`atlas doctor` подтверждает согласованность состояния.

Полный вывод всех команд пишется в `/var/log/atlastunnel/atlas.log`.

## Удаление

```bash
atlas uninstall sstp --yes
```

Останавливает и отключает службы (общие с другими протоколами — не трогает),
снимает правила iptables по метке `atlas:<протокол>`, удаляет учётные записи
протокола и снимает его с учёта.

В интерфейсе то же самое: экран протокола → **Удалить протокол**.

### Файлы на сервере

| Путь | Назначение |
|------|-----------|
| `/etc/atlastunnel/*.conf` | маркеры установленных протоколов, режим 600 |
| `/etc/atlastunnel/ca-cert.pem` | CA-сертификат для клиентов IKEv2 |
| `/etc/atlastunnel/clients/*.ovpn` | готовые профили OpenVPN, режим 600 |
| `/etc/ppp/chap-secrets` | учётные записи PPTP, L2TP, SSTP |
| `/etc/ipsec.secrets` | PSK и учётные записи EAP |
| `/etc/sstp-server/cert.pem` | самоподписанный сертификат SSTP |
| `/opt/atlastunnel/sstp/` | venv с демоном SSTP из PyPI |
| `/etc/letsencrypt/renewal-hooks/deploy/atlastunnel.sh` | перезапуск SSTP после продления |
| `/etc/atlastunnel/legacy.conf` | пакеты, взятые из архива прошлого выпуска |
| `/etc/apt/sources.list.d/atlastunnel-legacy.list` | подключённый архив прошлого LTS |
| `/etc/apt/preferences.d/atlastunnel-legacy` | закрепление приоритетов apt |
| `/var/log/atlastunnel/atlas.log` | журнал всех выполненных команд |
| `/run/atlastunnel.lock` | межпроцессная блокировка |

## Отличия от v4

- Транзакции с откатом вместо необратимых частичных изменений
- Конфликт `/etc/ipsec.conf` проверяется для всех трёх IPsec-протоколов, а не для одной пары
- SSTP наконец работает: демон ставится из PyPI, а не несуществующим `apt-get install sstp-server`, и больше не затирает `/etc/ppp/chap-secrets`
- Пакеты из архивов прошлых выпусков ставятся через apt с проверкой подписи и точечным закреплением, а не `wget` конкретных `.deb` с вшитыми версиями и без проверки
- PPTP получил реальное шифрование: `noccp` и `nomppe` рядом с `+mppe-128` отключали MPPE
- OpenVPN выпускает клиентский сертификат и `.ovpn` — раньше подключиться было нечем
- Пароли 16 символов (~93 бита) вместо 8 (~47 бит), в интерфейсе скрыты по умолчанию
- Публичный IP берётся из трёх источников и проверяется — строка-заглушка больше не попадёт в сертификат
- IPv6 не отключается глобально
- Правила iptables помечаются и снимаются при удалении протокола
- Для SSTP доступен доверенный сертификат Let's Encrypt по `--domain` с автопродлением
- Появились `atlas doctor`, `atlas uninstall`, `--json` и неинтерактивный режим

### Обновление бинарников в репозитории

Готовые сборки лежат прямо в `bin/` — отдельные выпуски на текущей стадии не
публикуются. Пересобрать и обновить их:

```bash
tools/deploy.sh --build-only
```

Собираются обе архитектуры (x86_64 и aarch64) и пересчитывается `bin/SHA256SUMS`.
Требуется Rust 1.74+ на машине сборки.
